dreamland has a first-party react-router equivalent that supports most of the features react-router has.
It's designed to be a singleton component that is controlled via the `router` export in `dreamland/router`.
The router is constructed as a JSX component and routes are defined in JSX:

```tsx
<div id="app">
	<Router>
		<Route show={<MainPage />} />
		<Route layout={DocsLayout} path="docs">
			{docs.map(({ path, component }) => {
				return <Route path={path} show={() => jsx(component, {})} />;
			})}
		</Route>
	</Router>
</div>
```

Once a `Router` component is created, the instance is exposed by the `router` export.
The `Router` automatically handles the `popstate` event for history navigation.
It also exposes a `navigate` function to change the current route and commit it to history:

```tsx
import { router } from "dreamland/router";

router.navigate("/"); // sent to history
```

## Advanced route usage

### Dynamic routes

Route path segments with `:<name>` creates a dynamic prop for that path segment, and `*` consumes all further path segments and puts them in the `*` prop.
All `show` targets get a prop `routerParams`, an object that has any props from the path segment.

You can't rely on it always existing since the router does not construct the `show` target internally with the `routerParams` prop passed in.
Instead, the `routerParams` prop is assigned to the component state during routing.

### Layouts

Layouts are special components that get more information about routing and wrap children routes.
The router constructs the layout component internally, passing the `routerState` prop.

## Async routes (Suspense)

The router also supports `show` props that are functions that return promises, allowing for code splitting and lazy loading.
The component returned is cached and not reinstantiated.

By default, routing does not show any feedback while waiting for async routes to finish.
However, layouts can use `routerParams` to show a loading bar or placeholder.

### Corking
"Corked" routes are routes with a layout that are only fully instantiated on the client and eagerly switch to their layout when navigating in from other pages.
This allows for clientside only routes for browser-only things like Monaco.

Make a route with a layout corked using the `cork={true}` prop.

## SSR integration

dreamland's router is compatible with SSR and hydration. By default, it'll attempt to route to `[location.pathname, location.origin]` which won't work in SSR environment,
but this can be overridden with the `initial` prop:

```tsx
import { render } from "dreamland/ssr/server";

function App(this: FC<{ url?: string }>) {
	return (
		<div id="app">
			<Router initial={this.url ? [this.url, "http://127.0.0.1:5173"] : []}>
				{/* ... */}
			</Router>
		</div>
	)
}

export default (path) => render(<App url={path} />);
```

### Prerendering

The router also exposes a `ssgables` function which returns any route that doesn't have dynamic parameters in it to allow for easy prerendering.

```tsx
let paths = router.ssgables();
let template = /* index.html ... */;

for (const [route, path] of paths) {
	const rendered = await renderSsr(template, () => entry.default(route));
	console.log(`prerendered: ${route}`);
	let resolved = resolve("dist/static/" + path);
	await mkdir(dirname(resolved), { recursive: true });
	await writeFile(resolved, rendered);
}
```
